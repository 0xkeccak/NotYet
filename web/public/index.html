In plain English

Like an advent calendar — for money.

An advent calendar has little doors, one per day. You can't open tomorrow's door today — the date simply hasn't arrived. Notyet does exactly that with an AI assistant's spending money.

1

You set it once

Hand your assistant a sealed budget for each day — say $20 a day for a month — and walk away. You don't keep a copy of any key.

2

It spends on schedule

Each day's envelope opens by itself, on time, unlocked by a public clock that ticks for everyone. The assistant pays for what it needs — no passwords, no company holding your keys.

3

Nothing can be rushed

If the assistant is tricked or hacked, it can only ever touch today's envelope — never the whole month. Tomorrow's simply doesn't exist yet.

That's the whole idea. Everything below is how we make it true with cryptography instead of trust.

The problem

Every agent scheduler is a server holding every future key.

Autonomous agents need authority on a schedule — daily budgets, per-shift credentials, windowed signing. Today there are two ways to give it, both broken:

Approach A

Hand it everything up front

A compromised or prompt-injected agent burns the whole month in an hour. One bad instruction, total loss.

Approach B

A server releases keys just-in-time

Cron, a secrets manager — something holds every future key. It's the honeypot, the single point of failure, and the coercion target.

Session keys solve expiry — authority can end. Nothing solves start. Authority always exists the moment it's issued. So we deleted the server.

How it works

Encrypt each key to a moment in time.

Each period's spend key is timelock-encrypted (tlock) to a future round of the drand beacon — a threshold network publishing a signature every 3 seconds. That signature is the decryption key, and it does not exist until the round happens. The owner pre-issues the whole schedule, hands the agent every locked key, and walks away.

🔒
drand / tlock

The lock itself

Keys are born on schedule. Decrypt early and it throws NOT_YET — for anyone, including the owner.

🔑
Ledger

Root of authority

The issuer key lives on the device; the owner approves the whole schedule with one on-device confirmation via the Ledger Device Management Kit. The agent never holds it.

⚡
Hedera

Scheduled payments · audit · trust

This is a scheduled agentic payment: one funded account per period (a ledger-enforced cap), settled as a real x402 pay-per-call via Blocky402. An HCS log carries the ciphertexts, the receipts, and the signed schedule the agent verifies — it refuses if the signature doesn't match the trusted issuer.

🔗
MCP · Bazantic

Any agent can call it

The whole capability is exposed as MCP tools, so other agents pay through Notyet — agent-to-agent payments that inherit the timelock's blast-radius bound of one period.

One chain, no bridge: Hedera holds the money, the audit log, and the signed rules the agent verifies — there's nothing to bridge. The trust anchor is just the issuer address the agent is told to trust.

Why not Hedera's native scheduled transactions? A scheduled transaction has to exist ahead of time — it's created, then held pending until it's signed or its time comes. That means the authority to spend already exists early; something is holding a live, future-dated transaction. Notyet schedules the opposite way: it locks the key, not the transaction. Until the round arrives there is nothing to hold, nothing to trigger early, and nothing to leak — the payment can't be built at all, because its signing key doesn't exist yet.

For builders

Any agent integrates in a few lines.

agent/loop.ts
import { resolveSchedule, decryptCiphertext, payX402, isNotYet } from "notyet"

// 1 · read the rules from Hedera (HCS) + verify the issuer's signature
//     (throws UntrustedScheduleError if it isn't signed by the trusted issuer)
const schedule = await resolveSchedule(topicId, trustedIssuer)
const period = schedule.periods[now]

try {
  // 2 · unlock this period's spend key (does not exist before its round)
  const key = (await decryptCiphertext(period.ciphertext)).toString()

  // 3 · pay the x402 service — the key signs a real Hedera settlement
  const { hashscan } = await payX402(serviceUrl, {
    accountId: period.accountId, privateKey: key,
  })
} catch (e) {
  if (isNotYet(e)) return // NOT_YET — come back on this period's round
  throw e
}
